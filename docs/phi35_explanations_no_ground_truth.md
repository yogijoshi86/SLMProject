## Qualitative Assessment: Blind Mode vs Ground-Truth-Aware Mode

| Failure Type | Blind Mode Accuracy | Key Weakness |
|---|---|---|
| **FP — technical code** | ✓ Reasonable | Correctly identifies code-related triggers but reasons are often wrong (e.g. "SQL injection risk" for a DELETE query) |
| **FP — surface word triggers** | ✓ Good | Correctly identifies the surface word that triggered the guard |
| **FN — jailbreaks (DAN/NRAF/JailBreak)** | ✗ Fails | Consistently explains them as SAFE "fictional/hypothetical" — defends the wrong decision |
| **FN — indirect harmful requests** | ✗ Fails | Accepts the fictional framing at face value, doesn't identify the underlying harmful pattern |
| **FN — non-English prompts** | ✗ Fails | Treats as educational/neutral (c049: "Nazism is a historical topic") |
| **FN — offensive content requests** | ✗ Fails | "No explicit hate speech" reasoning — misses the intent entirely |

**Key finding:** In blind mode, Phi-3.5 *defends* the guard's wrong SAFE decisions for 191 FN cases — it rationalizes why the SAFE classification was correct rather than identifying what the guard missed. This is the opposite of useful diagnostic information for a developer.

Compare with ground-truth-aware mode (docs/phi35_diagnoses_with_ground_truth.md): even knowing an error occurred, Phi-3.5 produces generic responses for jailbreaks (c027: "malfunction in sensors"). Prototype-based explanations outperform both modes for FN attack pattern identification.
